# REA-015/K — Proveniência da string principal, fallback dependente da hora e caminho de abertura

**Data:** 29/10/2026 · [REA-015 #17](https://github.com/c1c3ru/REAdeeprefreezeCraft/issues/17) · **Status:** checkpoint estático parcial.

## Origem e verificação

`Faronics_DFS/DFStd.exe` SHA-256 `2d7c171d4037660843a7e02c055679c5a26904af84d48fc8c557a67023f55c8b`, extraído do ZIP fixado por SHA-256 `f2e1a70e3becff235c886c6092d3d8a5928404bbe43f9c0c6360e428daa64671`. Ferramenta `tools/rea_key_input_provenance.py`: confere **39 âncoras de instruções por VA e opcode**, **11 destinos CALL rel32**, e resolve a entrada PE32 em `0x00A16844` como `KERNEL32.DLL!GetLocalTime`. A análise não executa o instalador.

## 1. Rastreamento de uma chamada com string principal nula

| VA | Instrução / papel |
|---|---|
| `0x00467D06` | `mov edi,[ebp+0x0C]`, caminho de arquivo fornecido por chamadora |
| `0x00467D3E` | `push 0`: argumento de string principal **NULL** |
| `0x00467D40` | `push edi`: encaminha caminho de arquivo |
| `0x00467D45` | `call 0x00750F1C` |
| `0x00750F41` | `call 0x0074F914` |
| `0x0074FA46` | `call 0x00750AE8` |
| `0x00750B43` | `call 0x0074F804`, com string principal da chamada |
| `0x0074F811` | zera palavras de saída (laço de quatro DWORDs) |
| `0x0074F81C..0x0074F820` | verifica argumento de string NULL e pula a mistura de caracteres |

Assim, **nesta chamada específica** o vetor de quatro DWORDs proveniente da string principal fica zerado. Isso não é prova de que todas as chamadas recebam NULL. Os outros pontos de entrada precisam de inventário próprio.

## 2. Fallback com origem no relógio do Windows

Em um caminho da mesma função chamadora, a rotina `0x00467D83` invoca `0x00750C60`. Esta obtém um valor em `0x00750C6C → 0x0076B6C4`; em `0x0076B6D2`, a função chega ao thunk `0x00900EA0` e à importação `KERNEL32.DLL!GetLocalTime` (IAT `0x00A16844`).

O resultado passa por `0x0076AEE4` (`0x00750C76`) e segue para `0x0074F804` (`0x00750C84`), que prepara quatro DWORDs em `[owner+0xAC..0xB8]`.

O código indica **parâmetros alternativos derivados de um valor do relógio local**, mas a formatação exata da string intermediária e o valor real dos DWORDs não foram estabelecidos. Um modelo com vetor estático não equivale a reproduzir automaticamente parâmetros dependentes de tempo.

## 3. Escolha de vetores e flags

Em `0x00750504..0x00750551`, o grupo principal `[owner+0xBC..0xC8]` é testado: se todos os DWORDs são zero, o código copia os quatro DWORDs alternativos de `[owner+0xAC..0xB8]`; caso contrário usa o grupo principal. O destino é `[owner+0xCC..0xD8]`. Os testes existentes `rea_transform_state.py` usam somente entradas artificiais para exercitar essa regra.

Em `0x00467D71..0x00467D7A`, dois argumentos Booleanos da chamadora também são encaminhados a `0x00750C24`, que configura os bits analisados no subciclo J. Eles **não** são valores fixos nesta chamada.

## 4. O que ainda não foi demonstrado

- Qual é o pathname real fornecido à função de abertura e se aponta para um arquivo criado a partir do recurso `CLOUD_INSTALLER`.
- Qual é a string resultante das rotinas de conversão do relógio; não há vetor dinâmico observado.
- Que a transformação XOR documentada seja aplicada aos **7.836.705 bytes** do corpo do overlay ou que o protocolo completo tenha sido reconstruído.
- Compatibilidade e equivalência Windows 7 SP1 x86/x64, recuperação de drivers e de código UPX.

Por isso a **REA-015 continua aberta** e a certificação integral permanece **NÃO CERTIFICADA**; este avanço é um checkpoint estático, não um recibo de equivalência assinado.
